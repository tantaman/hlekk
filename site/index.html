Abstract. An object has a type and payload. Edges between objects can span databases. Queries are hops between objects. The engine spreads a database over as many hosts as required.

† Old Norse for a chain link.

the whole idea

1 Introduction

Hlekk is a TAO-style [1] object-and-edge database. The application gives locality hints, such as creating a comment with its issue. The engine owns capacity and moves shards between hosts. A database starts on one host and grows to many with no application changes.

2 An edge into another database

An edge’s target may be a reference: another database’s URI, a number sign, and a local id.

// In the notes database. The target is a reference, not an id.
await notes.assocAdd(noteAbout, note,
  "https://wiki.example/db#281474976710691");

// And one query brings the page back from the wiki.
const [row] = await Note.gen(note)
  .related("about", noteAbout).run(notes);
row.about[0].title; // "Country"

Listing 1. One edge out, one query back.

a URI,
not an id!

Different people run the two databases. The query crosses over HTTP, and the wiki decides what the notes database may see.

3 Running one

$ npm install
$ node src/adapters/node/serve.ts --dir ./my-database \
    --port 8080 --path /db
$ curl http://127.0.0.1:8080/db              # the descriptor
$ curl http://127.0.0.1:8080/db/vocabulary   # types and edges

Listing 2. A whole database.

A directory of SQLite files, one process, and the protocol on a port. No account anywhere. A second one, with an edge drawn at its URI, is a federation. It also runs on Cloudflare Durable Objects, Rivet and celld.

5 What it does not do

  1. (a)Foreign writes. Not in version 1. A database writes only to itself.
  2. (b)Backlinks across databases. A database that wants one subscribes.
  3. (c)A global directory. A URI is the name; DNS arbitrates it.
  4. (d)Many databases in one deployment. One deployment, one database.
  5. (e)A permission model. The caller is a trusted server.
