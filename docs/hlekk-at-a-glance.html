Hlekk

Old Norse for a chain link.

A TAO-style object-and-edge database built on actors, targeting any actor platform with durable local storage — Durable Objects, celld, Rivet. Hlekk owns partitioning, placement and capacity.

Four layers, and the id is what holds them together.

THE GRAPH

What the application writes: typed objects with a JSON payload, and typed, ordered associations between them. Nothing else.

THE ID

Stable and unique for the life of the graph. It is both the name of an object and the route to it, which is why a cross-database read needs no lookup.

LOGICAL DATABASES

The unit of placement. Each owns a slab of the id space, so two of them can never mint the same id, and each can be moved whole.

ACTORS

The machines. One actor holds many logical databases until some of them get hot; a small graph is one actor, and growing to many changes no application code.
